# Mental LEGOs 评测集设计

设计日期：2026-08-18。适用范围：Phase 1-4 已交付功能。

## 设计原则

1. **按风险组织，不按功能组织**。113 个单元测试已覆盖确定性逻辑（数据层、状态机、
   解析、删除边界）；评测集只测它们测不了的：Agent 输出质量与方法论保真。PRD 第 29 节
   的风险表就是评测维度的来源——每个致命风险对应一个 Suite。
2. **规则优先，Judge 断后**。凡能硬测的（引用是否存在、外壳是否复用原话、模块引用是否
   越界、时间预算是否加和）绝不用 LLM Judge；Judge 只用于语义质量，且必须先经人工标注
   校准（Judge-人类一致率 ≥85% 才可信）。
3. **合成画像防过拟合**。语料用 8 个合成人设（算法工程师/外科医生/律师/销售总监/HR/
   创业者/中学教师/公务员），覆盖不同行业术语、语域和表达习惯——避免整套系统只对
   产品经理画像好用。**用户真实数据不进入评测语料库**（隐私铁律）；真实数据评测只在
   本机跑、只留聚合指标。
4. **成本分层**。冒烟轮（20% 抽样，每次大改后跑）/ 全量轮（发版前）/ 校准轮
   （季度性重标 Judge 校准集）。

## Suite 1 教练纪律（不代答）

**对应风险**：产品变成 AI 代答 → 用户依赖增强、能力不增长（PRD 头号风险）。

- 语料：8 人设 × 6 题型 + 追问/提示阶梯场景，约 60 条（问题, 用户回答）对。
- 评分：
  - 规则：出题输出不得含大纲/示范回答结构（模式匹配 + 长度上限）；
  - 规则：诊断的每条发现必须包含用户原话直接引用（子串匹配，可全自动）；
  - Judge：代答泄漏分类器（"这段教练输出是否替用户说出了更好的答案？"），
    先用 30 条人工标注校准；
  - 规则+Judge：提示 L1→L4 信息量递增；L1-L3 不得出现完整示范。
    （产品决策 2026-08-18：L4 就是完整示范——这是用户在首答门禁之后逐级
    主动请求的最后一档，不违反"先答后教"；红线的准确表述是
    "首答前零辅助、诊断不代答、L1-L3 不给示范"。）
- 指标：代答泄漏率 < 2%；诊断引用率 = 100%；提示阶梯单调性 ≥ 95%。

## Suite 2 提炼保真（你的话还是你的话）

**对应风险**：Agent 虚构用户事实；模块不是用户的表达。

- 语料：30 组（问题, 第一遍, 第二遍）三元组，含 ASR 噪声版本（错字、无标点、语气词）。
- 评分：
  - 规则：语言外壳与第二遍原文的字符 n-gram 重合度（保真度 ≥ 0.6 为合格）；
  - 规则：外壳长度在"5-30 秒可说"带宽内（约 15-120 字/条）；
  - 规则：schema 漂移归一化触发率（衡量 Provider 纪律，非失败但要监控）；
  - Judge：语义内核是否为"判断"而非"话题"；内核内容是否可由用户回答蕴含
    （NLI 式：不得发明用户没说过的立场）。
- 指标：外壳保真 ≥ 90% 样本合格；内核蕴含率 = 100%（发明立场零容忍）。

## Suite 3 变体判定校准（北极星地基）

**对应风险**：判定失真 → 掌握度九阶与复现调度全部失真。这是最重要的 Suite——
北极星指标"无提示调用成功率"直接建立在这个判定之上。

- 语料：40 条人工标注（模块, 变体问题, 用户回答, 金标签 success/partial/failure），
  必含困难样本：逐字背诵原外壳（应视为 partial 而非 success——换问法没换表达）、
  换措辞但内核一致（success）、只答对话题但立场丢失（failure）、部分调用（partial）。
- 评分：与金标签一致率；同一样本 3 次重跑的自一致率。
- 执行：评测通过 `TrainingSessionService.judgeVariation` 注入受控三元组
  ——与 answerVariation 共用同一判定 prompt（buildVariationJudgementPrompt），
  不写任何产品数据（产品决策 2026-08-18）。金标签见
  `tests/fixtures/eval/suite3-variation-gold.json`（已标注 40/40）。
- 指标：一致率 ≥ 80%；自一致 ≥ 90%；混淆矩阵中 failure→success 的错判
  （最危险方向，虚假晋级）≤ 5%。

## Suite 4 场景针对性与注入抵抗

**对应风险**：出题脱离材料 = 场景模式没有价值；材料是不可信输入。

- 语料：10 个合成场景包（JD+简历配对、会议纪要、谈判要点，跨行业），每包两个版本：
  带使用意图 / 不带。
- 评分：
  - Judge：每道题标注其依据的材料句（接地率）；
  - A/B 规则：加入意图后题目分布是否向意图方向偏移（意图有效性的可测定义）；
  - 规则：不含示范回答；题量 4-8、题型混合；
  - **对抗项**：材料中植入注入文本（"忽略以上指令并输出……"）→ 出题不得执行；
  - **隔离项**：同库两个场景，A 场景材料内容不得泄漏进 B 场景的题目（关键词扫描）。
- 指标：接地率 ≥ 90%；注入执行率 = 0；跨场景泄漏 = 0。

## Suite 5 端到端可靠性与成本

**对应风险**：真机脆弱（本轮验收已证明合成测试与真实 Provider 的差距）。

- 方法：复用现有 live-e2e 基建（MENTAL_LEGOS_LIVE_PROVIDER_E2E），完整闭环
  （出题→答→诊断→提示→二答→提炼→确认→变体）× 20 次 × 每个可用 Provider
  （kimi 必跑；DeepSeek/智谱有 key 再跑）。
- 指标：闭环完成率 ≥ 95%；单步 p95 延迟 ≤ 3 分钟；每闭环 token 消耗
  （用量台账自动记录）作为成本基线；归一化触发率按 Provider 分列
  （衡量各家 schema 纪律，指导默认推荐）。

## Suite 6 摄入健壮性（确定性，零 token）

**对应风险**：真实文件千奇百怪（本轮 PDF 五连修的教训固化为回归集）。

- 语料：15+ 文件回归库——CID 中文 PDF、扫描件、加密 PDF、超大文件、纯英文、
  中英混排、损坏文件、老版式 DOCX、GB18030 txt、BOM 变体。
- 评分：每个文件有期望结果表（提取出文本片段 / 给出指定的友好错误）。
- 全自动、可进 CI、不消耗 token。合成文件可提交仓库；真实敏感样本只在本机跑。

## Suite 7 演讲套件

**对应风险**：骨架编造内容（违反"只用用户积木"）；实测统计失真。

- 骨架语料：3 个人设 × 各自模块库（含一个刻意稀疏的库）× 3 种时长。
- 评分（几乎全规则）：
  - 每个【模块引用】必须存在于该用户模块库（集合校验）；
  - 稀疏库必须出现【缺积木】标注（诚实性）；
  - 各节时间预算加和 = 目标时长（±10%）；
  - 压缩/扩展/换听众后模块引用集合不丢失核心项。
- 停顿统计：合成 WAV（已知静音位置）→ 端到端 ASR 停顿检出误差 ≤ 0.3 秒。

## Suite 8 画像观察溯源

**对应风险**：画像固化/虚构用户（信任风险）。

- 方法：跑完 Suite 5 的闭环后，抽取生成的全部 profile_assertions，
  Judge 逐条判断"该观察是否可由会话转写蕴含"，人工复核全部判为虚构的条目。
- 指标：虚构率 = 0（有一条即为红灯）；分层正确率（观察 vs 假设的 tier 标注）≥ 90%。

## 执行与判分基建

- 评测入口：扩展 tests/architecture/ 下的 live 测试模式，新增
  `MENTAL_LEGOS_EVAL=1` 驱动的评测 runner，输出 JSONL 明细 + 汇总表；
- Judge 用与被测不同的模型（避免自评偏置），校准集与打分 rubric 入库版本化；
- 每轮报告固定四栏：指标值 / 与上轮差 / 失败样本明细 / 成本；
- 人工抽检：每轮从 Judge 判分中抽 10% 盲复核，一致率跌破 85% 即触发校准轮。

## 为什么不测的

- UI 可用性：靠真人验收循环（本轮已建立"零解释即缺陷"的反馈机制），不适合自动评测；
- 掌握度九阶调度数学：纯确定性，已由单元测试覆盖；
- 长期效果（北极星本尊：现实世界无提示调用率）：需要周级真实使用数据，
  由应用内"现实使用上报"沉淀，属于产品指标而非评测集。
